# 商协会网页结构化脚本留存与产品报价采集

提取 HTML 中 application/ld+json 脚本及原文位置,保存原页,并按登记的上下文
把脚本解释成语义图,给出可追溯的主产品、报价与卖方关联结果。

## 运行

在 Python 3.11 或更新版本的 Linux 环境使用。原始内容保存在 `output/raw.sqlite3`,删除 `output/` 可回到干净状态。全部示例使用本地合成数据,不包含账号凭据或真实企业资料。

```sh
python3 -m unittest discover -s tests -v
python3 -m compileall -q .
python3 app.py demo                 # 采集 fixtures 页面并输出关联分析
python3 app.py analyze              # 用当前上下文登记重新解析库中原页
python3 app.py show <摘要>          # 按摘要查看原页、原脚本或历史分析
```

`--output` 指定另一份原文库,`--contexts` 指定另一份上下文登记,`--fixtures` 指定另一组页面。正常执行不到 30 秒。

## 模块与数据

fixtures 提供图引用、上下文别名与冲突报价的本地页面;`fixtures/contexts.json` 是远程上下文的本地登记副本。

`raw_store.py` 将原始字节按 SHA-256 保存,用来源和字节摘要区分观察。它只保存原文,不表达业务结果是否完整。同一内容重复观察保留一份对象并更新观察时间,SQLite 事务保证对象和观察同时提交。所有解析异常保持非零退出码,输入原件不改写。

`linked_source.py` 只提取页面中的 JSON-LD 原脚本及行列位置,不做语义解释。

`semantics.py` 是 JSON-LD 子集解释器,规则如下:

- 上下文支持本地与远程形式、词项别名、前缀、@base、@vocab、语言映射、
  嵌套 @graph 与 @id 引用。远程上下文只从预先登记的本地副本解析,运行时
  不访问网络;未登记或循环的上下文写入"上下文问题",对应脚本不参与构图。
- 相对 @id 按各脚本有效 base(脚本 @base → 页面 base/canonical)解释;
  匿名节点身份带页面摘要前缀,不跨页面串用;数组始终保留为多个值,不
  折叠成唯一值。
- 先连接语义图再识别业务对象:主产品只认 @id 与页面规范地址(canonical)
  一致的产品节点,不按可见页面位置猜测;报价与卖方必须经 offers/seller
  显式引用才接入,没有显式关联的推荐卡片列入"未接入主产品"。
- 同一 @id 跨脚本出现可补充属性;价格或币种出现多个不同值时保留全部
  候选并阻止该报价发布;缺少币种不默认任何币种;语言版本各自保留,
  不互相覆盖。
- 输出中每个业务字段带来源(脚本序号、行号、JSON 路径、脚本摘要),
  可用 `python3 app.py show <脚本摘要>` 回看原始脚本。

## 重新解析与变化区分

每次解析把分析结果连同页面摘要(正文版本)与上下文登记摘要(语义解释
版本)一起入库。再次运行时对比上一次记录:正文不变而解释变化时报
"语义解释变化",解释不变而正文变化时报"正文变化"。更新上下文副本后
执行 `python3 app.py analyze` 即可重新解析库中原页,无需重新抓取。

## 环境

`requirements.txt` 登记精确依赖。环境准备阶段安装依赖,运行、构建及测试不执行下载。正式运行可以使用依赖准备后记录的镜像 ID;镜像和验证回执保存在项目外,不影响原始内容。
